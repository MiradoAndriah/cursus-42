# Call Me Maybe

## Description

Call Me Maybe converts natural-language prompts into structured function calls. It uses the provided `Small_LLM_Model` SDK and the Qwen/Qwen3-0.6B model. The model selects a function and generates its arguments with constrained decoding.

The program does not execute the selected function. It only produces a JSON description of the call.

## Instructions

### Requirements

- Python 3.10 or newer
- `uv`
- Internet access on the first run to download the model

### Installation

```bash
uv sync
```

### Run

From the project root:

```bash
uv run python -m src
```

Optional arguments:

```bash
uv run python -m src \
  --functions_definition data/input/functions_definition.json \
  --input data/input/function_calling_tests.json \
  --output data/output/function_calling_results.json
```

The output file is created automatically. Do not commit `data/output/`; it is generated when the program runs.

## Algorithm

1. Load and validate the function definitions and prompts with Pydantic.
2. Load the model vocabulary and build an ID-to-token mapping.
3. Give the available function descriptions and the user prompt to the LLM.
4. Constrain function-name generation to names declared in the definitions.
5. Generate each argument according to its declared type (`number`, `string`, or `boolean`). Invalid token choices are masked with negative infinity before selecting the next token.
   - Numbers follow the JSON number grammar (a token is allowed only if the text stays a valid prefix); strings only accept characters and escapes valid inside a JSON string. Both have a length limit.
6. Assemble the JSON object from fixed structural text and constrained values.
7. Parse the generated JSON and validate the function name, parameter names, and parameter types before writing the result. A prompt that fails validation is skipped with an error message; the others are still written.

## Design decisions

- The provided `llm_sdk` is used for model inference; no private SDK attributes are accessed.
- Pydantic validates input definitions and output records.
- JSON structure and parameter names are assembled from the function schema instead of asking the model to write arbitrary JSON keys.
- Each value generator has a finite token limit to avoid an endless generation loop.
- The model chooses the function; the code only restricts choices to the available schema.

## Performance analysis

The project targets at least 90% correct function selection and argument extraction, 100% parseable/schema-compliant JSON, and a total runtime below five minutes on standard hardware, as required by the subject.

Measure the actual accuracy and runtime on the evaluation machine before reporting benchmark results. Results depend on hardware, model download/cache status, and the test prompts. The implementation validates output structure and types, but this validation alone does not prove 90% semantic accuracy.

## Challenges

- A small model can confuse similar function descriptions or extract incorrect arguments.
- Token-level generation must respect the expected type while allowing multi-token values.
- Token generation must stop safely when a complete value has been produced.

The implementation addresses these issues with schema-restricted function selection, type-specific token constraints, generation limits, and final validation.

## Testing strategy

Run the supplied test set, then test additional prompts that are not present in the examples. Include empty strings, quotes and backslashes, special characters, negative and decimal numbers, large numbers, ambiguous requests, unknown requests, and functions with several parameters.

After each run, check that `data/output/function_calling_results.json`:

- is valid JSON;
- contains exactly `prompt`, `name`, and `parameters` in each result;
- uses a declared function name;
- contains exactly the required parameter names and types.

Useful checks:

```bash
uv run python -m src
uv run flake8 .
uv run mypy . --warn-return-any --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs
```

## Example usage

Input prompt:

```json
{"prompt": "Add 12 and 30"}
```

Example output shape:

```json
[
  {
    "prompt": "Add 12 and 30",
    "name": "fn_add_numbers",
    "parameters": {"a": 12.0, "b": 30.0}
  }
]
```

The values above illustrate the expected format; actual results are generated by the model.
